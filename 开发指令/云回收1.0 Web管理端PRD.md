# 云回收 1.0 Web 管理端产品需求文档（PRD）

> 文档定位：指导 Web 管理端的产品、设计、前端、云函数和验收工作。  
> 适用版本：云回收 1.0  
> 文档状态：开发基线稿  
> 更新日期：2026-07-16

## 1. 文档背景

云回收是一个预约上门回收小程序。普通用户在微信小程序中提交回收订单，管理员在 Web 管理端查看订单、联系用户、安排上门、登记实际回收结果，并在线下完成付款后上传打款凭证。

1.0 的目标是先形成可运行的业务闭环，不包含线上支付、自动打款、财务对账或工作人员独立端。

## 3. 产品目标

### 3.1 业务目标

1. 让管理员能及时发现新订单并推进处理。
2. 完整记录订单从提交到完成或取消的全过程。
3. 确保“已完成”订单具有实际回收数量、最终金额和打款凭证。
4. 让运营人员可自主维护回收品类和最低起收标准，减少代码发版。

### 3.2 用户目标

管理员进入后台后，应能够：

- 在最少操作下找到需要处理的订单。
- 在一个订单详情中看到决策所需的所有信息。
- 清楚知道每个状态可执行的下一步操作。
- 在不满足完成条件时获得明确、可操作的错误提示。

### 3.3 1.0 成功标准

- 管理员可通过微信扫码成功登录。
- 新订单可在 Web 后台被查询、查看和处理。
- 只允许使用四种订单状态。
- 不满足完成条件的订单无法被标记为已完成。
- 品类修改和最低起收配置能影响小程序用户端的业务规则。

## 4. 用户与权限

### 4.1 用户角色

1.0 只设置一种 Web 端角色：管理员。

| 角色 | 身份来源 | 权限 |
|---|---|---|
| 管理员 | 微信 OpenID 存在于 `admins` 白名单且 `enabled=true` | 查看全部订单、修改订单、维护品类、修改系统配置 |

1.0 不区分运营、调度、财务和超级管理员。

### 4.2 权限原则

- Web 端不直接读写数据库。
- 所有数据操作必须通过 `quickstartFunctions` 云函数。
- 除创建/查询登录票据外，所有管理接口必须带 `sessionToken`。
- 前端的菜单隐藏、按钮禁用不构成权限边界；权限必须由云函数再次校验。
- 会话失效、管理员被停用时，立即返回登录页。

## 5. 范围

### 5.1 1.0 范围（P0）

- 微信扫码登录。
- 订单列表、状态筛选、订单号搜索和分页。
- 订单详情。
- 订单处理：状态、估价、实际量、最终金额、回收人员、取消原因和管理备注。
- 打款凭证上传、预览和回显。
- 品类新增、编辑、排序、上架和下架。
- 最低起收标准配置。
- 加载、空状态、错误、会话过期和操作反馈。

### 5.2 建议纳入（P1）

- 列表按联系人姓名或手机号搜索。
- 预约日期范围筛选。
- 待处理订单数量提示。
- 订单更新后的二次确认或操作结果摘要。
- 品类排序拖拽。
- 表单离开时的未保存提示。

### 5.3 不在 1.0 范围

- 线上支付、自动打款、提现。
- 优惠券、积分、分销。
- 复杂财务对账和会计凭证。
- 工作人员独立 Web/小程序端。
- 多角色和细粒度菜单权限。
- 批量更新订单。
- 微信订阅消息。
- AI 物品识别。

## 6. 信息架构与页面路由

### 6.1 一级导航

| 导航 | 建议路由 | 优先级 | 主要任务 |
|---|---|---|---|
| 订单管理 | `/orders` | P0 | 查询、查看和处理订单 |
| 品类管理 | `/categories` | P0 | 维护小程序回收品类 |
| 系统配置 | `/settings` | P0 | 配置最低起收规则 |

登录页建议路由为 `/login`。订单详情可使用 `/orders/:id` 页面路由，或根据 Figma 稿保持右侧抽屉；两种方式的业务内容和验收标准一致。

### 6.2 全局框架

登录后框架应包含：

- 产品标识。
- 一级导航。
- 当前页标题和必要说明。
- 当前管理员名称。
- 退出登录入口。
- 当前导航高亮和页面加载状态。

## 7. 核心业务规则

### 7.1 订单状态

1.0 只允许以下四种状态：

| 状态值 | 显示名称 | 含义 | 后续操作 |
|---|---|---|---|
| `submitted` | 已提交 | 用户刚提交，等待平台处理 | 转处理中或取消 |
| `processing` | 处理中 | 已联系用户、安排上门或回收中 | 完成或取消 |
| `completed` | 已完成 | 已回收、金额确认并存在打款凭证 | 终态 |
| `canceled` | 已取消 | 用户或管理员取消，或物品不可回收 | 终态 |

### 7.2 状态迁移

| 当前状态 | 可转移状态 | 条件 |
|---|---|---|
| 已提交 | 处理中 | 管理员确认开始处理 |
| 已提交 | 已取消 | 必须填写取消原因 |
| 处理中 | 已完成 | 满足完成订单的全部条件 |
| 处理中 | 已取消 | 必须填写取消原因 |
| 已完成 | 无 | 终态，1.0 不支持恢复 |
| 已取消 | 无 | 终态，1.0 不支持恢复 |

旧状态迁移规则：

| 旧值 | 新值 |
|---|---|
| `confirmed` | `processing` |
| `assigned` | `processing` |
| `recycling` | `processing` |
| `rejected` | `canceled` |

### 7.3 完成订单校验

将订单修改为 `completed` 时，必须同时满足：

1. 最终金额已填写，且大于或等于 0。
2. 实际回收量已填写：
   - 按重量计量的订单：实际重量必填。
   - 按件数计量的订单：实际件数必填。
   - 混合单位订单：至少填写一种实际量，具体数据模型需后端确认。
3. `transferProofs` 至少包含一个有效云存储 `fileID`。
4. 当前状态为 `processing`。

校验必须同时存在于前端和云函数。前端用于及时反馈，云函数是最终业务边界。

### 7.4 取消订单校验

- 管理员把订单改为 `canceled` 时，`cancelReason` 必填。
- 旧数据中的 `rejectReason` 应迁移或映射为 `cancelReason`。
- 取消后不允许在 Web 端直接恢复。

### 7.5 金额规则

- 品类参考价不自动生成最终金额。
- `estimatePrice` 是平台估价，可选。
- `finalPrice` 是线下实际付给用户的最终金额。
- 金额精度为两位小数，展示时统一使用人民币和“元”。
- 系统不处理真实资金流转，只保存结果和凭证。

## 8. 核心用户流程

### 8.1 扫码登录

1. 管理员打开 Web 管理端。
2. Web 请求 `adminCreateLoginTicket`。
3. 页面展示小程序码和过期提示。
4. 管理员使用微信扫码，进入小程序确认页。
5. 小程序调用 `adminConfirmLoginTicket`，云函数根据 OpenID 校验白名单。
6. Web 使用 `ticket + webNonce` 轮询 `adminCheckLoginTicket`。
7. 确认成功后，Web 保存短期 `sessionToken` 并进入订单管理页。

当前后端默认：登录二维码有效期 5 分钟，管理会话有效期 12 小时。

### 8.2 处理新订单

1. 管理员进入订单列表，选择“已提交”。
2. 查看联系人、预约时间和订单摘要。
3. 打开详情，查看物品、照片、地址和备注。
4. 联系用户并安排上门。
5. 必要时填写估价、回收人员和管理备注。
6. 将订单状态更新为“处理中”。

### 8.3 完成订单

1. 管理员打开“处理中”订单。
2. 填写实际重量或实际件数。
3. 填写最终金额。
4. 上传至少一张打款凭证。
5. 修改状态为“已完成”。
6. 前端展示完成信息摘要并要求确认。
7. 云函数重新校验后保存，写入 `completedAt`。
8. 页面显示保存成功，列表和详情同步刷新。

### 8.4 取消订单

1. 管理员在“已提交”或“处理中”订单中选择“取消订单”。
2. 填写取消原因。
3. 页面明确提示取消后 1.0 无法恢复。
4. 管理员二次确认。
5. 云函数保存 `cancelReason` 和 `canceledAt`。

## 9. 页面详细需求

### 9.1 登录页

#### 目标

让管理员在不输入独立账号密码的情况下，通过微信白名单安全登录。

#### 页面内容

- 产品名称“云回收管理后台”。
- 登录标题和简短说明。
- 小程序码。
- 当前登录状态。
- 刷新二维码按钮。
- 必要的开发环境降级提示。

#### 页面状态

| 状态 | 页面反馈 |
|---|---|
| 初始化 | 展示骨架或“正在生成登录码” |
| 待扫码 | 展示二维码和“请使用微信扫码” |
| 已扫码/待确认 | 如后端可识别，展示“请在小程序中确认” |
| 无权限 | 小程序端提示无权限；Web 端不获取会话 |
| 已过期 | 隐藏或蒙层处理旧二维码，提供“刷新二维码” |
| 生成失败 | 展示原因和重试入口；开发环境可展示小程序路径 |
| 登录成功 | 停止轮询并进入订单管理 |

#### 验收标准

- 未登录时无法访问管理页面数据。
- 二维码过期后不再继续有效轮询。
- 刷新时先停止旧轮询，再生成新票据。
- 登录成功后刷新页面，在会话未过期时可恢复登录状态。
- 会话过期时清理本地会话数据并返回登录页。

### 9.2 订单列表

#### 页面目标

帮助管理员快速定位新订单、识别状态并进入处理。

#### 列表字段

| 字段 | 展示规则 | 优先级 |
|---|---|---|
| 订单号 | 完整展示，支持复制建议为 P1 | P0 |
| 订单状态 | 使用文字+状态标签，不可只依赖颜色 | P0 |
| 用户信息 | 联系人姓名+手机号 | P0 |
| 上门地址 | 省市区+详细地址，过长时省略，可查看完整内容 | P0 |
| 订单摘要 | 品类或拍照提交摘要 | P0 |
| 预约时间 | 日期+时间段 | P0 |
| 金额 | 有最终金额时优先显示，否则显示估价，均无时显示—” | P0 |
| 创建时间 | 年-月-日 时:分 | P0 |
| 操作 | 查看详情、处理订单 | P0 |

#### 查询条件

- 订单状态：全部、已提交、处理中、已完成、已取消。
- 订单号：支持包含搜索，去除首尾空格。
- 点击查询时回到第 1 页。
- 点击重置时清空所有条件并回到第 1 页。
- 默认按 `createTime` 倒序。
- 默认每页 20 条，后端单页上限 50 条。

#### 页面状态

- 首次加载。
- 查询中。
- 有数据。
- 当前条件无数据。
- 系统内尚无订单。
- 请求失败，可重试。
- 会话过期。

#### 分页

- 展示当前页和总条数。
- 首页时“上一页”禁用。
- 无更多数据时“下一页”禁用。
- 筛选条件修改后重新查询应回到第 1 页。

#### 验收标准

- 列表仅出现四种新状态。
- 搜索、筛选、分页参数和返回数据一致。
- 同一时刻只有一次有效查询结果覆盖列表，避免旧请求后返覆盖新结果。
- 地址、备注或摘要过长时不破坏表格布局。
- 云函数错误不以原始错误码作为唯一用户提示。

### 9.3 订单详情

#### 信息分组

1. 订单概览：订单号、状态、来源、创建时间、更新时间。
2. 用户与上门信息：联系人、联系电话、地区、详细地址、预约日期、预约时间段。
3. 物品信息：提交方式、品类、预估重量/件数、订单摘要。
4. 用户材料：物品照片、用户备注。
5. 回收处理：平台估价、实际重量/件数、最终金额、回收人员姓名/电话、管理备注。
6. 完成或取消结果：打款凭证、完成时间，或取消原因、取消时间。

#### 图片交互

- 物品照片和打款凭证分组展示。
- 缩略图应保持比例并裁切，加载失败时显示失败状态。
- 点击缩略图可大图预览。
- 打款凭证对用户端可见，上传前应提示管理员确认图片中不包含不应公开的信息。

#### 验收标准

- 拍照提交订单能显示全部物品照片。
- 已完成订单能显示最终金额和打款凭证。
- 已取消订单能显示取消原因。
- 空字段使用统一空值符号“—”，不显示 `null`、`undefined` 或原始字段名。
- 加载详情失败时可重试或关闭详情。

### 9.4 处理订单

#### 表单字段

| 字段 | 控件 | 必填条件 | 校验 |
|---|---|---|---|
| 订单状态 | 选择器或按状态显示的动作按钮 | 必填 | 只能选择合法下一状态 |
| 平台估价 | 数字输入 | 否 | ≥0，最多两位小数 |
| 实际重量 | 数字输入 | 按重量完成时必填 | >0，单位 kg |
| 实际件数 | 整数输入 | 按件数完成时必填 | 正整数 |
| 最终金额 | 数字输入 | 完成时必填 | ≥0，最多两位小数 |
| 回收人员姓名 | 文本输入 | 建议必填 | 去除首尾空格 |
| 回收人员电话 | 电话输入 | 建议必填 | 中国大陆手机号基础校验 |
| 打款凭证 | 图片上传 | 完成时必填 | 至少 1 张 |
| 取消原因 | 多行文本 | 取消时必填 | 去除首尾空格后不为空 |
| 管理备注 | 多行文本 | 否 | 建议上限 500 字 |

#### 打款凭证上传

- 支持点击选择和拖放上传。
- 默认支持 JPG、PNG 和 WebP。
- 建议单张不超过 10 MB，最多 9 张；最终限制需与云存储能力统一。
- 选择后立即显示本地预览、文件名和上传状态。
- 上传失败的单张图片可单独重试或删除。
- 保存前必须等待所有图片上传完成。
- 存储路径：`transfer-proofs/{orderNo}/{timestamp}-{random}.{ext}`。
- 上传成功后把 `fileID` 写入 `transferProofs`。
- 移除已保存凭证应进行二次确认；是否同步删除云存储源文件由后端策略决定。

#### 保存交互

- 提交期间禁用重复提交。
- 普通更新成功后显示成功反馈。
- 完成和取消属于终态操作，提交前应二次确认。
- 保存失败时保留已填内容和已上传图片，不自动关闭表单。
- 保存成功后更新列表中对应订单。

#### 验收标准

- 前端不展示非法状态选项。
- 不满足完成条件时，不发起完成请求。
- 即使绕过前端，云函数仍拒绝非法状态和缺失字段的完成请求。
- 完成后详情可查看最终金额、实际量、打款凭证和完成时间。
- 取消后详情可查看取消原因和取消时间。

### 9.5 品类管理

#### 列表字段

- 品类名称。
- 计量单位：`kg` 或“件”。
- 参考价文案。
- 排序值。
- 上架状态。
- 编辑操作。

#### 新增/编辑字段

| 字段 | 必填 | 规则 |
|---|---|---|
| 名称 | 是 | 去除首尾空格后不为空 |
| 单位 | 是 | 限定为 `kg` 或“件” |
| 参考价 | 否 | 文案字段，例如“0.8元/kg起”，不参与最终金额自动计算 |
| 排序 | 否 | 整数，数值越小越靠前，默认 0 |
| 状态 | 是 | 上架/下架，默认上架 |
| 图标 | P1 | 当小程序端支持动态图标时开放 |

#### 业务规则

- 品类下架不删除历史订单中的品类快照。
- 1.0 不提供品类物理删除，需下线时使用“下架”。
- 同一排序值的稳定次序需由后端约定；建议以创建时间或 `_id` 作为第二排序键。
- 已下架品类在管理端仍然可见和编辑。

#### 验收标准

- 新增或编辑成功后，列表立即反映最新值。
- 下架品类不再出现在小程序用户端可选列表中。
- 编辑品类不修改历史订单快照。
- 表单校验失败时保留输入。

### 9.6 系统配置

#### 配置项

| 字段 | 默认值 | 控件 | 规则 |
|---|---:|---|---|
| 最低起收重量 `minWeightKg` | 5 | 数字输入 | ≥0，单位 kg |
| 最低起收件数 `minCount` | 0 | 整数输入 | ≥0；0 表示不启用件数门槛 |
| 拍照订单校验最低起收量 `photoOrderCheckMinQuantity` | false | 开关 | 关闭时，拍照提交不校验最低起收量 |

#### 交互规则

- 页面进入时读取当前有效配置。
- 没有配置记录时显示默认值。
- 保存前展示该规则对用户下单的影响说明。
- 保存成功后显示成功反馈和最后更新时间。
- 保存失败时保留当前输入。

#### 待产品确认

- 重量和件数同时大于 0 时，是“满足任一条件”还是“同时满足”。
- 拍照订单开启校验后，用户未填写可量化数值时如何判断。

#### 验收标准

- 非法数值无法提交。
- 保存后重新进入页面，展示上次保存的值。
- 小程序新建订单使用最新规则进行校验。
- 系统配置接口必须校验管理会话。

## 10. 全局交互与状态

### 10.1 加载

- 页面首次加载使用稳定的骨架、表格占位或明确加载文案。
- 按钮触发请求后显示提交中状态，禁止重复点击。
- 页面局部更新不应使整个页面白屏。

### 10.2 空状态

- 无数据和无筛选结果应使用不同文案。
- 无筛选结果时提供“清除筛选”。
- 品类为空时提供“新增品类”。

### 10.4 成功反馈

- 查询和页面切换不弹出成功提示。
- 保存订单、保存品类和保存配置成功后，显示轻量成功提示。
- 完成、取消等终态操作在提交前二次确认，成功后明确告知新状态。

## 11. 设计与体验要求

### 11.1 设计基线

- 页面视觉、信息密度、导航样式、表格、表单、状态标签、抽屉/弹窗以 Figma 《废品回收管理后台》为参考。
- 未在 Figma 中覆盖的页面状态，应沿用同一套设计语言，不另起一套风格。
- 当 Figma 和本 PRD 在业务规则上冲突时，以本 PRD 为准；当视觉属性冲突时，以确认后的 Figma 稿为准。

### 11.2 响应式

- 核心对象为桌面管理后台，建议优先适配 1280px 及以上宽度。
- 1024–1279px 时页面仍应可完成全部 P0 操作。
- 768–1023px 时导航可折叠，表格可横向滚动或转为信息列表。
- 小于 768px 不作为主要使用场景，但登录、订单查看和紧急状态更新不应完全不可用。

### 11.3 可用性与无障碍

- 所有表单控件必须有明确标签。
- 键盘用户可访问导航、筛选、表格操作、弹窗和上传。
- 弹窗/抽屉打开后焦点进入容器，关闭后返回原触发元素。
- 错误不只通过红色表达，状态不只通过颜色区分。
- 图片必须有可理解的替代文本。
- 动态成功/错误消息应能被辅助技术读取。
- 主要文字和背景的对比度应满足 WCAG AA 的常用文本标准。

### 11.4 可见性与敏感信息

- 联系人、手机号、上门地址和打款凭证仅在通过管理会话校验后返回。
- 不在前端日志、错误提示或 URL 中输出 `sessionToken`、OpenID 和完整个人信息。
- 打款凭证的临时访问 URL 不作长期持久化。

### 13.2 Web 端统一响应处理

Web 端按以下结构处理云函数响应：

```ts
type CloudResult<T> =
  | { success: true; data: T }
  | { success: false; errMsg: string; data?: unknown };
```

- `success=true` 时读取 `data`。
- `success=false` 时通过错误码映射用户可理解文案。
- 未识别的错误统一显示“操作失败，请稍后重试”，详细错误仅写入受控开发日志。

## 15. Web 端实施建议（非产品强制）

### 15.1 建议技术栈

对后续持续开发，建议使用：

- Vite
- React
- TypeScript
- React Router
- 请求状态管理库可选，不作强制
- CloudBase JS SDK
- CloudBase 静态网站托管

当前不需要 SSR、SEO 或 Next.js API Routes，因此不必为 1.0 强制引入 Next.js。

### 15.2 建议模块划分

```text
src/
  api/              CloudBase 初始化、接口和错误映射
  auth/             会话、扫码轮询和路由守卫
  components/       公共表格、表单、上传、状态标签
  features/orders/  订单列表、详情和处理
  features/categories/
  features/settings/
  layouts/          管理后台框架
  routes/           页面路由
  types/            订单、品类、配置和响应类型
```

### 15.3 静态托管约束

- 构建结果为静态文件，部署到 CloudBase 静态网站托管。
- 使用前端 History Router 时，托管端需配置 SPA 回退到 `index.html`；如不能配置，使用 Hash Router。
- 云环境 ID 属于可公开的前端运行配置，但不应把私密密钥放入前端环境变量。
- 正式环境和开发环境必须使用不同的配置和数据。

## 16. 非功能需求

### 16.1 性能

- 列表只请求当前页所需字段。
- 图片临时 URL 仅在详情页需要时换取。
- 搜索、分页或页面切换不产生重复并发请求。
- 表格数据加载时保留页面框架，避免布局跳动。

### 16.2 安全

- 不将 `sessionToken` 写入 URL、分析事件或普通日志。
- 用户生成内容展示时必须避免 HTML 注入。
- 文件上传校验类型、大小和数量。
- 云函数不信任前端传入的状态、金额、文件标识和权限信息。
- 打款凭证和地址属于敏感信息，仅在业务所需范围展示。

### 16.3 兼容性

- 优先支持当前主流版本的 Chrome 和 Edge。
- Safari 作为 P1 验收。
- 不支持 Internet Explorer。

### 16.4 可维护性

- 订单状态在前端定义为统一类型，不在多页重复维护字符串。
- 云函数错误码与用户文案集中映射。
- 金额、日期、电话和空值展示使用统一格式化函数。
- 页面不通过未经处理的 HTML 字符串渲染用户数据。
