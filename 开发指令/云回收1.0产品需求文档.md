# 云回收 1.0 产品需求文档

> 本文用于指导当前项目 1.0 版本重构与后续开发。  
> 当前阶段只做两个端：微信小程序用户端、Web 管理端。  
> 后续可能增加工作人员小程序端，但不放进 1.0 必做范围。

## 1. 项目背景

云回收是一个预约上门回收的小程序。

用户在小程序里提交回收订单，填写要回收的物品、上门地址、预约时间和联系方式。后台管理人员看到订单后，安排回收人员上门。回收人员到现场后确认物品、重量和金额，管理人员再在后台修改订单金额和状态。

1.0 版本不做线上打款。平台只记录订单和金额，实际给用户的钱由线下完成。这样可以先把业务跑起来，避免一开始就处理微信支付、企业付款、提现、风控、资金合规等复杂问题。

当前小程序是个人主体注册，用于临时开发和测试。后续正式上线时，需要迁移到企业主体的小程序，这一点在开发时必须提前考虑。

## 2. 产品目标

1. 用户可以方便提交上门回收订单。
2. 用户可以看到自己的订单状态和最终金额。
3. 管理人员可以在 Web 管理端查看订单、修改订单信息、填写金额、更新状态。
4. 平台可以把回收业务完整记录下来：谁下单、回收什么、什么时候上门、最终多少钱、订单是否完成。
5. 1.0 版本先不处理线上支付和自动打款，金额只做记录。

## 3. 端和角色

### 3.1 微信小程序用户端

给普通用户使用。

用户能做的事：

- 查看可回收品类。
- 选择品类后预约上门回收。
- 不确定物品品类时，可以拍照提交。
- 填写或选择上门地址。
- 选择预约上门时间。
- 提交订单。
- 查看自己的订单列表和订单详情。
- 在订单还没进入处理前取消订单。
- 查看后台确认后的金额和订单结果。

### 3.2 Web 管理端

给平台内部管理人员使用。

管理端需要鉴权。能进入管理端的人，默认就是管理员，不再细分运营、财务、调度等角色。

管理员能做的事：

- 查看所有用户提交的订单。
- 按订单状态筛选订单。
- 查看订单详情，包括用户地址、电话、物品、照片、预约时间和备注。
- 修改订单状态。
- 修改订单金额。
- 修改订单实际重量或数量。
- 填写回收人员信息。
- 填写管理备注。
- 维护可回收品类。

### 3.3 后续工作人员小程序端

这不是 1.0 必做内容，但需要提前预留方向。

后续可以增加一个工作人员使用的小程序端。工作人员登录后可以看到分配给自己的回收订单，上门后在手机上确认重量、金额和订单状态。

到那个阶段，订单处理就可以从 Web 管理端逐步下放给工作人员端。

## 4. 权限说明

1. 用户端只能看自己的订单和地址。
2. 用户端不能修改订单金额。
3. 用户端不能修改订单状态，除了允许取消还没开始处理的订单。
4. 管理端能看所有订单。
5. 管理端能修改订单状态、金额、重量、回收人员和备注。
6. 管理端只需要区分“能不能进入后台”。能进入后台的人就是管理员。
7. 管理端登录建议使用小程序扫码确认登录，再通过管理员 OpenID 白名单判断权限。

## 5. 主业务流程

### 5.1 用户下单流程

```text
用户进入小程序
→ 查看首页和回收入口
→ 选择按品类预约，或选择拍照提交
→ 填写物品信息
→ 选择上门地址
→ 选择预约时间
→ 提交订单
→ 订单进入“已提交”状态
```

### 5.2 后台处理流程

```text
管理员进入 Web 管理端
→ 查看新订单
→ 联系用户或确认订单信息
→ 安排回收人员上门
→ 修改订单状态为“处理中”
```

### 5.3 上门回收流程

```text
回收人员上门
→ 现场确认物品、重量、数量和金额
→ 线下把钱给用户
→ 管理员在 Web 管理端填写实际金额并上传打款截图
→ 管理员把订单状态改为“已完成”
```

### 5.4 拍照提交流程

```text
用户拍照提交不确定的物品
→ 管理员在后台查看照片
→ 如果可以回收，继续安排上门
→ 如果不能回收，后台联系用户后取消订单或备注说明
→ 用户在订单详情里看到结果
```

## 6. 订单状态

| 状态 | 含义 | 谁操作 |
|---|---|---|
| 已提交 | 用户刚提交订单，等待平台处理 | 用户提交后自动生成 |
| 处理中 | 平台已接单，正在联系用户、安排回收人员或上门回收 | 管理员，后续可由工作人员端处理 |
| 已完成 | 已上门回收，金额、重量和打款截图可按需补充 | 管理员 |
| 已取消 | 用户或平台取消订单 | 用户或管理员 |

1. 用户只能取消“已提交”的订单。
2. 管理员确认回收已完成后即可将订单改为“已完成”。
3. 最终金额、实际重量/件数和打款截图均为选填，不影响订单改为“已完成”。
4. 订单完成后，用户端只展示结果，不允许用户再修改。
5. 如果订单无法回收，管理员把订单改为“已取消”，并填写取消原因。

## 7. 金额和打款规则

1. 小程序里展示的品类价格只是参考价。
2. 订单金额不自动计算。
3. 最终金额由现场回收结果决定。
4. 管理员可在 Web 管理端手动填写最终金额。
5. 管理员可按需上传打款记录截图。
6. 打款截图用于证明回收人员已经把钱转给用户。
7. 平台不通过系统给用户打款。
8. 实际打款通过线下方式完成，例如微信转账、现金或其他人工方式。
9. 系统只记录最终金额、打款截图和订单状态，不单独记录线下打款方式。
10. 打款截图附属在订单详情里，用户端和管理端都可以查看。

这样做的原因是：平台给用户自动打款需要企业资质、微信支付商户能力、出款能力、风控审核和财务流程，1.0 阶段不适合一开始就做。

## 8. 用户端功能

### 8.1 首页

首页展示：

- 当前定位区域。
- 主要入口：按品类预约、拍照提交。
- 可回收品类。
- 我的订单入口。

### 8.2 品类选择

用户可以选择一个或多个回收品类。

品类信息包括：

- 品类名称。
- 计量单位，比如 kg 或件。
- 参考价格文案。
- 是否上架。
- 排序。

### 8.3 提交订单

用户提交订单时需要填写：

- 回收方式：按品类预约或拍照提交。
- 物品信息：品类、预估重量、预估数量或照片。
- 上门地址。
- 联系人和联系电话，手机号来自地址里的联系电话，必须填写。
- 预约日期。
- 预约时间段。
- 备注。

提交规则：

- 按品类预约需要满足最低起收标准。
- 最低起收标准由管理端配置。
- 拍照提交是否受最低起收标准限制，由管理端配置决定。

### 8.4 地址管理

用户可以：

- 新增地址。
- 编辑地址。
- 删除地址。
- 设置默认地址。
- 使用地图选点辅助填写地址。

订单提交后，订单里保存的是地址快照。用户后续修改地址，不影响已经提交的历史订单。

### 8.5 我的订单

用户可以查看：

- 全部订单。
- 进行中的订单。
- 已结束的订单。

订单列表展示：

- 订单号。
- 订单摘要。
- 订单状态。
- 预约时间。

### 8.6 订单详情

订单详情展示：

- 订单状态。
- 物品信息。
- 照片。
- 上门地址。
- 预约时间。
- 用户备注。
- 后台估价。
- 最终重量。
- 最终金额。
- 打款记录截图。
- 取消原因。

## 9. Web 管理端功能

### 9.1 登录

管理端通过微信扫码登录。

登录方式：

```text
Web 管理端生成二维码
→ 管理员用微信扫码
→ 打开小程序确认登录
→ 后台判断该微信 OpenID 是否在管理员白名单里
→ 通过后进入 Web 管理端
```

管理端不做复杂角色。只要能登录，就默认是管理员。

### 9.2 订单列表

订单列表需要展示：

- 订单号。
- 订单状态。
- 用户姓名。
- 用户电话。
- 上门地址。
- 预约时间。
- 订单摘要。
- 最终金额。
- 创建时间。

列表需要支持：

- 按状态筛选。
- 按订单号搜索。
- 查看详情。
- 进入处理订单。

### 9.3 订单详情

管理员可以查看：

- 用户提交的所有信息。
- 物品照片。
- 地址和联系方式。
- 预约时间。
- 订单状态。
- 估价和最终金额。
- 打款记录截图。
- 备注。

### 9.4 修改订单

管理员可以修改：

- 订单状态。
- 平台估价。
- 最终重量。
- 最终金额。
- 打款记录截图。
- 回收人员标识或姓名。
- 取消原因。
- 管理备注。

订单改为“已完成”时，以下信息均可按实际情况选填：

- 最终金额可按实际情况选填。
- 订单实际重量或数量可按实际情况选填。
- 打款记录截图。

### 9.5 品类管理

管理员可以维护可回收品类：

- 新增品类。
- 修改品类名称。
- 修改单位。
- 修改参考价。
- 修改排序。
- 上架或下架品类。

## 10. 迁移约束

当前小程序是个人主体，用于临时开发和测试。后续正式上线时，需要迁移到企业主体小程序。

迁移时需要注意：

- 个人主体小程序上的用户身份，不能直接等同于企业主体小程序上的用户身份。
- 管理员白名单需要在正式小程序里重新确认。
- 如果临时小程序里产生了真实订单，需要在迁移前做数据整理。
- 正式小程序需要重新确认服务类目、隐私协议、定位权限和地图能力。
- 正式环境上线前，需要确认 Web 管理端的正式访问地址。

## 11. 1.0 范围

1.0 必须包含：

- 用户端首页。
- 品类选择。
- 拍照提交。
- 地址管理。
- 提交订单。
- 我的订单。
- 订单详情。
- 用户取消订单。
- Web 管理端扫码登录。
- Web 管理端订单列表。
- Web 管理端订单详情。
- Web 管理端修改订单状态和金额。
- Web 管理端完成订单时上传打款截图。
- Web 管理端配置最低起收标准。
- Web 管理端品类管理。

1.0 暂不包含：

- 线上支付。
- 自动给用户打款。
- 用户提现。
- 优惠券。
- 积分。
- 分销。
- 复杂财务对账。
- 工作人员小程序端。
- 消息推送。
- AI 自动识别物品。

## 12. 后续版本方向

### 12.1 工作人员小程序端

后续可以增加工作人员端。

工作人员端主要做：

- 登录。
- 查看分配给自己的订单。
- 查看用户地址和电话。
- 标记准备上门。
- 到现场后填写实际重量和金额。
- 上传现场照片或打款截图。
- 修改订单为已完成。

### 12.2 消息通知

后续可以增加微信订阅消息。

通知场景：

- 订单已提交。
- 订单处理中。
- 回收人员已上门。
- 订单已完成。
- 订单已取消。

### 12.3 支付和打款

后续如果企业资质、微信支付和财务流程都准备好，可以考虑线上支付或自动打款。

但这不建议放进 1.0。

## 13. 当前需要确认的问题

下面这些问题不会阻塞 1.0 开发，但需要尽快确认：

1. 正式企业小程序的 AppID 什么时候能确定？
2. 回收人员信息 1.0 是否只填姓名/电话，还是需要维护人员列表？
3. 订单完成时是否还需要上传现场物品照片，还是只上传打款截图？
4. 最低起收标准按重量配置即可，还是需要同时支持按件数配置？
5. 拍照提交是否需要绕过最低起收标准？

已知前提：

- Web 管理端正式域名暂时未处理，先按开发环境推进。
